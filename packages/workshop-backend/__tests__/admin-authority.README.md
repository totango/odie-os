**Current owner evidence:** `admin-provider-evidence.test.ts` exercises typed native test bridges to actual Context registry/collection and JARVIS policy owners, two-scan challenge/domain/version/inventory validation, atomic activation and post-activation readiness. Provider-only real-workerd tests separately run actual vendor entrypoints: Context `__tests__/admin-fence.worker.test.ts`, and JARVIS's same-named test via Context `vitest.jarvis-admin-fence.config.ts` (existing Vitest4/pool, exact assertion alias; JARVIS Node/Vitest3 dependency unchanged). This avoids merging incompatible provider/backend Env programs without casts or widening shared base interfaces.

Retained old Context mutation wire calls now deny at owners. JARVIS old mutation wire shape denies; ordinary value-only get intentionally remains available. Expected immediate native-owner denials are caught inside `runInDurableObject` with exact error assertions to avoid the installed callable-thenable adapter's early queue release, not filtered globally. Other retained calls and all positive paths still use real native RPC. Issued Git write tokens are independent credentials: explicit fixture tests preserve them across admin removal and verify explicit authorized revocation; no real Artifacts calls occur. The historical vulnerability/blocked-build bullets below are superseded by [current contract](../../../docs/plans/hugin-community-requests/legacy-owner-fencing.md).

`admin-authority-worker.ts` exports the real backend, Context storage classes and JARVIS policy, plus local-only fixture entrypoints. `vitest.config.ts` runs it in workerd; no fixture entrypoint ships in the backend. No Finance stream/descendant/drain proof is implied.

## Scoped type program

The production declaration's backend-only `GlobalProps` cannot describe this combined Worker. `tsconfig.admin-authority-tests.json` instead loads **only** `admin-authority-configuration.d.ts`, generated by the same installed Wrangler/runtime as the repository. Its `mainModule` is `./admin-authority-worker`; the SQLite namespace list matches the executed fixture. `wrangler.admin-authority.jsonc` is declaration-generation input, not a deploy configuration. Native service props and fake bindings remain owned by the Vitest fixture; no live identifiers or credentials are used.

From the repository root (under the established protected, noCI/proven-store runner in this task):

```sh
pnpm --filter @gadgets/workshop-backend exec wrangler types __tests__/admin-authority-configuration.d.ts --config __tests__/wrangler.admin-authority.jsonc
pnpm --filter @gadgets/workshop-backend exec tsc --noEmit -p tsconfig.admin-authority-tests.json
pnpm --filter @gadgets/workshop-backend exec vitest run __tests__/admin-authority.test.ts
```

The generated bulk is isolated from production declarations and checked in alongside its input so runtime validation and direct typechecking do not require a new codegen task or mutate production types. Do not hand-edit it. Generator provenance is in its header (Wrangler 4.120.0, pinned workerd 1.20260801.1). No dependency declarations were changed.

The harness returns the actual `ContextApi` and `Pick<JarvisPolicyApi, "get" | "update">` surfaces. These preserve all public methods under test while avoiding a second native mapping of Cap'n Web `RpcPromise`/disposer internals. No mirrored RPC interfaces, casts, assertions removed, or transport behavior changes are involved.

The test-only `restore: symbol` module augmentation is the same missing-runtime-export declaration already used by `scripts/generate-worker-types.ts`. `LOADER: WorkerLoader` and `BROWSER: BrowserRun` cover imported backend source only: **neither is provided or exercised by this fixture**. Accidental access fails rather than fabricating provider success. PendingLogin is an actual local SQLite binding in both fixture configurations; no browser/loader is started.
