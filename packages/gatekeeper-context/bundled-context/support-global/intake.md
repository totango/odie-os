# Support intake checklist

Capture only the minimum context needed for routing: symptom, feature area, severity, business impact, reproduction confidence, timeframe, and whether the issue is ongoing.

Use customer-safe wording. Avoid copying identifiers, access tokens, screenshots with private data, or raw logs unless a separate approved tool explicitly requires them.

Default routing:

- Product question: answer from public docs or bundled context.
- Usage anomaly: inspect product-usage context first.
- Integration failure: verify configuration, auth state, and recent deploy or vendor changes.
- Data quality concern: ask for narrow examples and summarize patterns without storing private records.
