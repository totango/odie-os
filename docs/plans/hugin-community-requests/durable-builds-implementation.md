### Ownership and public boundary

- `RequestBuilds` lives in the existing `CommunityRequests` SQLite DO. `build_runs` owns immutable request revision/specification, initiating admin claim/generation, model/execution/publication policy snapshots, full canonical-main base SHA, attempt, receipt identity, cancellation, retry and publication evidence. `build_keys` records per-actor mutation receipts. One unique deployment-active slot is released only after acknowledged execution cleanup and no unresolved publication write.
- `AdminApi.startRequestBuild`, `cancelRequestBuild`, and `getRequestBuildReadiness` obtain a fresh purpose-bound claim from the real authority. Admission requires managed membership, actual initiating-user GitHub repository and model eligibility, and all readiness gates. Cancellation by any current administrator does not reuse the initiating administrator's authority.
- `AuthenticatedApi.getRequestBuild` is connector-independent and strictly projected: request/run IDs and revision, state/attempt/timestamps, stable error code, cleanup, verified PR number/URL and cancel-too-late. No private specification, actor, credentials, patch, raw output or provider errors. Hidden requests return null. Ordinary users cannot mint AdminApi; signed-out callers cannot read runs.
- Approval contains only submitted kind/title/body, not later user details or model text. Moderation monotonically changes request revision; hide/close/duplicate/revision drift blocks further work. A later restore/reopen never revives old approval.
- Alarms and constructor recovery own progress. No browser completion callback, arbitrary job framework, additional DO namespace, or client-supplied readiness is introduced.

### Restricted execution and publication

The existing Sessions durable reservation remains the execution authority. Backend authorization verifies the actual durable dispatch/session/generation/receipt, exact policy/specification/authority and phase. Publication additionally requires the exact persisted pending-operation digest. Reads/cleanup remain possible after initiator revocation; new model/publication operations do not.

The approved Stage-B race repair adds a permanent owner/dispatch cancellation fence, checked atomically with reservation. A resolved `cancelRequestBuildExecution(...): null` acknowledges that fence committed before reservation; an ordinary missing receipt or rejected cancellation is NOT cleanup proof. This closes delayed-ensure versus cancellation/capacity-release races.

Backend publisher independently parses the bounded diff, rejects protected/traversal/duplicate paths, binary/control/secret material, symlink/submodule/mode/rename changes, applies regular UTF-8 changes at exact hunk positions against verified frozen base blobs, and checks whole resulting Git trees. Regular creation/deletion is supported. Explicit path/line/text limits have no production defaults. Main movement denies new writes rather than silently rebasing approval.

Sessions owns only the private credential transport: fixed `api.github.com/repos/totango/odie-os`, repository-scoped short-lived GitHub App installation tokens, separate read/write scopes with returned-scope validation, bounded JSON/manual redirects/timeouts, fixed typed Git Data tree/commit/ref and draft-pull operations. No arbitrary URL, PATCH, force, merge or deploy operation exists. The transport checks the backend authorization after minting and immediately before its write. Credentials never enter the sandbox.

Deterministic branch/run/attempt and provenance body are backend-owned, not model output. Before every side effect its exact intent is durable. Tree contents, commit parent/tree/message, ref and draft PR repo/base/head/body/URL are verified through GitHub reads. Lost ref/PR acknowledgements reconcile without another write. Missing evidence is not absence: unresolved writes retain the slot in `needs_attention`. Unacknowledged tree/commit writes deliberately cannot be adopted without a trusted resulting hash; there is no automatic reset/force-retry escape hatch. Cancellation during an already-admitted PR may finish as `pr_created` with cancel-too-late, never falsely as an undone PR. Provenance explicitly says project verification tests were not run by the trusted control plane.
