## 1. Authority modes and compatibility

- **legacy** (initial/default): exact existing `ADMINS` account semantics remain effective, including all four configured principals. No automatic membership mutation, account creation, alias merge or bootstrap union on restart. Existing Finance owner/direct-share/admin behavior stays unchanged and explicitly unfenced.
- **prepared**: a one-time, explicit, revision-checked bootstrap records an operator-approved existing-account snapshot, generations and audit. Static membership remains effective; prepared membership is not an effective grant. Unknown/unresolved configured principals block preparation rather than being dropped. Source inspection cannot confirm live accounts or approve the four-versus-one discrepancy.
- **managed**: effective grant/revoke transactions are available only after legitimate cutover. No fallback to static membership on authority storage failure, including after restart or rollback. Preserve generations/history; fail closed on stale grant or evidence failure. Ordinary board participation does not depend on privileged readiness.

Implement actual `listAdministrators`, exact-account `resolveAdministratorCandidate`, private paged audit and bootstrap preview/preparation; show mode/effective versus prepared membership clearly. `grantAdministrator` and `revokeAdministrator` are real transaction implementations but return `ADMIN_MANAGED_NOT_ACTIVE` before managed mode. Do not queue an apparently successful revoke, edit static deployment config through UI, or claim Finance invalidation. In managed mode require current actor in the same synchronous transaction, expected revision, canonical mutation-key payload, no self-revoke, last-admin protection, and generation advancement on revoke/regrant. Replays recheck actor authority before returning receipts.

Backend-minted native `AdminAuthorization.assertCurrent()` has immutable private principal, deployment, purpose and mode/epoch provenance (plus grant generation for managed capabilities). A legacy capability re-evaluates the exact existing static principal **per admission**, not its mint-time boolean. Managed capabilities check current authority/generation without positive cache; legacy capabilities cannot be valid in managed mode. No caller chooses actor, grants or purpose. Known purpose domains are administration, board moderation, Context public management, JARVIS policy and request builds. Derive actual RPC types; do not import the arbitrary-Finance transport prototype into production.

Cover every `AdminApiImpl` privileged read/write, board hidden reads/moderation, app discovery/open and Context/JARVIS privileged operations. Keep Context private collection ownership independent. Existing `isAdmin` is presentation/legacy compatibility only on the new path; it never grants upgraded-path authority. Check immediately before external publication; already-admitted operations may finish, never retroactively undo an external write.

**Approved provider-first compatibility:** add an explicitly advertised capability-aware app-UI protocol to the real account description/interface. New backend uses that path only after trusted account/provider protocol evidence; absence blocks the new privileged path. It must never catch a denial/outage/arbitrary RPC error and retry boolean authorization. Providers retain the old `startAppUi` boolean path solely for old-backend compatibility during legacy rollout, avoiding an unapproved outage. This old path, pinned old account versions, old UI URLs/stubs and Finance descendants remain **unfenced drain inventory**, not managed-ready merely because new opens are checked. Before activation they must be fenced/retired and demonstrably drained; a version response alone proves neither. Provider protocol advertisement is compatibility information, never self-asserted admin or ambient authority.

## 2. Private readiness and transition contract

Use backend-owned code to assemble readiness; never accept readiness/evidence values from AdminApi, AdminConfig, browser, request content or model output. A read-only public/admin projection returns stable reason codes, not private evidence or credentials. Boolean `enabled`, an operator checkbox, a passing test or a build hash is not cutover proof. No cryptographic live attestation is invented.

Internal transition input is only an authorized request identifying the prepared revision and idempotency key. The transition implementation obtains evidence through its **backend-owned evidence provider**, checks deployment/authority epoch, bootstrap revision and covered surfaces, then performs a revision-checked synchronous authority transaction. Evidence is not caller-supplied, serialized as a bearer token or stored in KV as positive authority. Any async acquisition requires revalidation of its local revision at commit; no network I/O in SQL transactions. A future provider must establish actual containment/drain and its invalidation/epoch semantics, not merely return a timestamp. Until that provider exists, transition returns blocked and performs **no mode/membership change**.

Production currently cannot establish Finance arbitrary-descendant guarding or old-capability drain. Its genuine readiness result must therefore contain `FINANCE_GUARD_UNAVAILABLE` and `LEGACY_CAPABILITIES_UNDRAINED`; do not wire a speculative guard, allow an env override, or manufacture successful evidence. Tests may construct verified fixture evidence from local guard/drain controls through test-only wiring. The production constructor/factory has no injectable test override reachable from bindings, environment or RPC. Implementing the actual transactional transition against that internal contract is allowed; implementing an unsupported Finance proof is not.

| Gate / reason | Trusted source and enforcement |
|---|---|
| `ADMIN_AUTHORITY_UNAVAILABLE`, `ADMIN_MANAGED_NOT_ACTIVE` | Current AdminAuthority storage/mode; start, dispatch, model authorization and publish deny without it. No static fallback for new build writes. |
| `ADMIN_BOOTSTRAP_UNCONFIRMED` | Exact existing-account snapshot and explicit preparation; unresolved/missing seed or stale revision blocks transition. |
| `FINANCE_GUARD_UNAVAILABLE` | Actual reviewed complete Finance guard integration; absent today. Known-path checks do not satisfy it. |

Readiness is evaluated server-side for admission, not just disabled-button rendering. Never create an execution intent, sandbox, cost reservation or provider write on rejected start. Recheck phase-specific authority/policy at dispatch, each model admission and publication. If a prerequisite disappears later, deny new privileged work and persist cancellation/reconciliation; service-owned receipt reads, exact-generation cleanup and already-sent PR/notification reconciliation remain available without the revoked initiator. An in-flight send may have succeeded; do not report it canceled without reconciliation.

## 3. Real component integration contracts

**Restricted Sessions:** extend the existing `CodingSessionsService`/`GatekeeperVendor` private binding and `CodingSessionToolHostImpl`/`WORKSHOP_TOOLS`; no public webhook or sandbox-exposed build-control tool. `ensureRequestBuild(owner, frozenIntent)`, receipt lookup and service cancellation use a durable dispatch key, immutable intent hash, preallocated session ID, attempt/generation, monotonically increasing receipt sequence and explicit cleanup state. Reserve before external startup, reject mismatched replay, and reuse normal registry lifecycle/capacity infrastructure. Integrate due work with its existing single alarm. Owner and intent are backend-derived, not browser-authorized. Reject ordinary attach/editor/MCP/customization routes for build-mode sessions so their owner cannot inject publication input through a personal session surface.

Add a dedicated deny-by-default request-build sandbox on the **existing pinned** SDK/image, separate from ordinary sessions and private feedback jobs. Fixed one-repository read-only clone credentials; no personal plugins/skills/connectors/transcripts or write credentials. Do not inherit ordinary `enableInternet=true`/contents-write proxy policy. Actual configured model egress must reserve a conservative worst-case call cost before forwarding and enforce call/token/output limits; settle measured usage without releasing uncertain reservations. Reject unknown pricing/uncapped output or unsupported provider metering, rather than pretending post-hoc spend reporting is a cap. Wall-time expiry must kill/destroy the exact generation, not merely time out a local wait. No numeric production budgets or new model are chosen here.

**Backend runs/publisher:** wire AdminApi start/cancel and authenticated board run reads into the existing CommunityRequests deployment registry and its durable build tables/alarm. Freeze public specification/revision/hash and full base SHA; one deployment-active execution and one logical active run per request. Persist start receipts before dispatch; recover missing acknowledgements via Sessions receipts, never blindly create another random session. Preserve H0 state machine, cancellation races, sequence/generation checks, bounded backoff and cleanup capacity leases. An ambiguous process start becomes `needs_attention` with exact-generation teardown before explicit retry.

Trusted Worker-side GitHub publication validates the frozen artifact (bounded text, no protected paths/secrets, symlinks, submodules, binaries or mode changes) and alone receives repo-scoped write credentials. Verify deterministic run/attempt ref, base/head/artifact and exact canonical draft PR. Lost response probes/adopts matching provider evidence; conflict/uncertainty is `needs_attention`, never force push, blind duplicate PR, merge or deploy. Actual verification exits are recorded, not model claims. Hiding the request prevents new publication/public projection but cannot erase an already-sent PR.

**Slack and run UI:** backend durable outbox owns immutable deployment/run/attempt/verified-PR key; extend the private JARVIS notifier entrypoint with a request-build operation and receipt, not the legacy feedback payload. Fixed-template request/run/PR links only; validate allowed origin, no credentials/query/fragment, canonical repository PR URL and confirmed channel. Track notification separately from `pr_created`. An unverified receiver-dedupe contract means an ambiguous response is not blindly retried or marked sent; actual implementation may support explicit at-most-one-send/ambiguous reconciliation without claiming exactly-once. Unknown receiver schema remains a launch prerequisite, not a reason to ship a no-op notifier.

Frontend replaces the current unavailable control with real readiness/start/cancel/status RPCs and `/requests/<requestId>/runs/<runId>` projection, preserving signed-in any-user reading and hidden-request policy. Never expose session/sandbox IDs, private account IDs, transcripts, raw errors or bearer/control links. Admin UI shows static/prepared/managed truthfully; managed-only controls explain exact blockers. Pipeline real RPC calls and dispose owned stubs; React stores stubs inside objects, never directly as state.
